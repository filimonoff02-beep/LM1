### 1.2. локальный хост
Определите и запишите в отчет, можно ли получить доступ к приложению, работающему на локальном хосте, со следующих IP-адресов: 194.34.23.100 , 127.0.0.2 , 127.1.0.1 , 128.0.0.1.
- 194.34.23.100: Доступ невозможен, если приложение не настроено на прослушивание внешних интерфейсов.

- 127.0.0.2: Доступ возможен, так как это loopback-адрес, но только если приложение настроено на прослушивание этого адреса.

   Если IP-адрес начинается с 127., это loopback-адрес. 
Весь диапазон 127.0.0.0/8 зарезервирован для loopback-адресов.
Loopback-адреса — это специальные IP-адреса, которые используются для тестирования и взаимодействия с самим собой (локальным устройством). Они не передаются по сети и всегда указывают на устройство, с которого выполняется запрос.<br>

### 3.1 Скорость соединения
- Конвертируйте и запишите результаты в отчет: 8 Мбит/с в МБ/с, 100 МБ/с в Кбит/с, 1 Гбит/с в Мбит/с

1 байт = 8 бит,

1 мегабайт (МБ) = 1024 килобайт (КБ),

1 килобайт (КБ) = 8 килобит (Кбит).

1 гигабит (Гбит) = 1000 мегабит (Мбит).

* 1 Гбит/с = 1000 Мбит/с
* 8 Мбит/c = 1 Мбайт/с
* 100 МБ/с = 819200Кбит/с (800000)
819,200 Кбит/с — это точный расчет в двоичной системе.

800,000 Кбит/с — это упрощенный расчет в десятичной системе.

Оба варианта могут встречаться, но в информатике и технических расчетах правильнее использовать 819,200 Кбит/с.

## Часть 4. Сетевой брандмауэр

### 4.1. утилита iptables 

**Создай файл /etc/firewall.sh, имитирующий файрвол, на ws1 и ws2:**

 1) На ws1 примени стратегию, когда в начале пишется запрещающее правило, а в конце пишется разрешающее правило (это касается пунктов 4 и 5)
 2) На ws2 примени стратегию, когда в начале пишется разрешающее правило, а в конце пишется запрещающее правило (это касается пунктов 4 и 5).
 3)  Открой на машинах доступ для порта 22 (ssh) и порта 80 (http).
 4)  Запрети echo reply (машина не должна «пинговаться», т. е. должна быть блокировка на OUTPUT).
 5)  Разреши echo reply (машина должна «пинговаться»).<br>

 ![ipatables](./img/ф3.png)

Пояснение:

1) iptables -F - очищает все правила в таблице фильтрации.
2) iptables -X - очищает все правила в таблице фильтрации.
3)  iptables -A OUTPUT -p icmp --icmp-type echo-reply -j DROP :
 * -A OUTPUT - добавляем правило в цепочку исходящего трафика
 * -p icmp - это означает, что правило применяется к протоколу ICMP (именно этот протокол используется для пинга).
* --icmp-type echo-reply - это конкретный тип ICMP-пакетов (echo-reply означает "ответ на пинг").
* -j DROP - говорит iptables просто отбросить пакет, то есть заблокировать.
4) iptables -A INPUT -p tcp --dport 22 -j ACCEP и iptables -A INPUT -p tcp --dport 80 -j ACCEPT:
* -A INPUT - добавляем правило в цепочку входящего трафика.
* -p tcp - правило применяется к TCP-пакетам.
* --dport 22 - это порт 22, который используется для SSH-подключений (доступ к серверу по командной строке).
* --dport 80 - это порт 80, который используется для HTTP (веб-сайты).
* -j ACCEPT - говорит iptables пропустить этот трафик.

**Запустите файлы на обеих машинах с помощью команд chmod +x /etc/firewall.shи /etc/firewall.sh**
- В отчёт помести скрины с запуском обоих файлов.<br>
![запуск скрипта](../src/img/Запуск%20обоих%20файлов.png)

- В отчёте опиши разницу между стратегиями, применёнными в первом и втором файлах.
 1) На WS1 была применена стратегия deny-first, при которой сначала запрещается ICMP-пинг, а потом разрешается
  - Запретить весь входящий трафик.

  - Разрешить входящий трафик только на порт 80 (HTTP) и 22 (SSH).
   - По умолчанию весь трафик блокируется, и только явно разрешённый трафик пропускается. 
 2) На WS2 была применена стратегия allow-first, при которой сначала разрешается ICMP-пинг, а потом запрещается
 - По умолчанию весь трафик разрешён, и только явно запрещённый трафик блокируется. 
 - Разрешить весь входящий трафик.

### 5.5. Построение списка маршрутизаторов

- Запусти на r1 команду дампа:
tcpdump -tnv -i enp0s3 <rb>

![tcpdump](./img/tcpdump%20.png)

- При помощи утилиты traceroute построй список маршрутизаторов на пути от ws11 до ws21.<rb>
![traceroute](./img/traceroute.png)

На основе вывода дампа на r1 объясните в отчете, как работает построение пути с помощью traceroute .
1. Первый шаг:
Traceroute отправляет пакет с TTL=1 на конечный IP. Этот пакет доходит до ближайшего маршрутизатора (R1).

R1 уменьшает TTL до 0.
Так как TTL=0, R1 отправляет обратно сообщение ICMP Time Exceeded.
2. Второй шаг:
Traceroute отправляет следующий пакет с TTL=2. Этот пакет доходит до следующего маршрутизатора (R2).

R2 также уменьшает TTL до 0 и отправляет ICMP-ответ обратно.
3. Следующие шаги:
Traceroute продолжает увеличивать TTL на 1 с каждым следующим запросом, пока пакет не достигнет конечной точки или не будет превышен лимит TTL.
